# 按反馈或变化修订

**何时使用**：开发者带着评审意见、未决问题或外部变化（需求、约束、平台），要求修订设计。

**输入**：现有设计、反馈或变化、未决问题。

**输出**：新版本设计；已解决或仍开放的未决问题；变化影响与修订理由。

**关键判断**：

- 变化影响哪些设计判断；
- 修订是否解决原问题；
- 是否引入新冲突；
- 哪些未决问题仍需开发者决定。

**边界**：不把“改完”当成“一定通过”；反馈有争议转 [`challenge.md`](challenge.md)；新冲突转 [`conflict.md`](conflict.md)。

**参考**：[`../references/design.md`](../references/design.md) 的修订场景；[`../references/template.md`](../references/template.md)。
