# 质疑并重判

**何时使用**：开发者不同意 Simon 的判断，要求解释、推翻或重判。

**输入**：争议判断、开发者的理由、相关设计文档。

**输出**：判断依据被展开；开发者决定采纳、推翻或要求重判；必要时形成新的判断或修订设计。

**关键判断**：

- 分歧在判据、事实还是假设；
- 原判断是否有依据；
- 是否需要重判；
- 推翻后哪些设计内容需要修订。

**边界**：不把“与既有方案不同”判为错误；不替开发者拍板；不承诺唯一答案。
