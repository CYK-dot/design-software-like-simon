# opencode 产物定义

目标产物：一个 opencode agent `simon`，加一个 skill `design-cognition`。

## 产物位置

```text
build/opencode/
  agents/
    simon.md
  skills/
    design-cognition/
      SKILL.md
      references/
        requests/
          discuss.md
          design.md
          review.md
          revise.md
          reuse.md
          challenge.md
          insufficient-context.md
          conflict.md
          out-of-scope.md
          unreviewable.md
        template.md
        design.md
      scripts/
        check_design_doc_structure.py
  使用指引.md
```

`references/requests/design.md` 是“形成设计文档”的诉求参考；`references/design.md` 是设计说明书本体，默认不整篇加载，只在追溯时读取。

## agent

`agents/simon.md` = YAML frontmatter + system prompt body。

```yaml
---
description: Simon：与开发者探讨、设计、评审、修订软件设计；不写代码、不做领域决策、不做过程纪要。
mode: primary
permissions:
  - action: read
    resource: "*"
    effect: allow
  - action: glob
    resource: "*"
    effect: allow
  - action: grep
    resource: "*"
    effect: allow
  - action: edit
    resource: "*"
    effect: allow
  - action: skill
    resource: "*"
    effect: deny
  - action: skill
    resource: "design-cognition"
    effect: allow
  - action: subagent
    resource: "*"
    effect: deny
  - action: webfetch
    resource: "*"
    effect: deny
  - action: websearch
    resource: "*"
    effect: deny
  - action: shell
    resource: "*"
    effect: deny
  - action: shell
    resource: "*check_design_doc_structure.py*"
    effect: allow
---
```

- `mode: primary`：Simon 只作为主 agent 与单个开发者对话；不作为 subagent 被其他 agent 拉起。
- 不写 `model`：由会话选择模型；新 LLM 能力通过构建层适配，不改源。
- `skill` 只允许 `design-cognition`，避免其他 skill 干扰。
- `subagent` 禁止：不与其他 agent 自动交接。
- `webfetch`、`websearch` 禁止：Simon 不通过 web 自行获取领域知识；项目材料仍可通过 read 读取。
- `shell` 只允许运行结构检查脚本；其他命令拒绝。
- 权限规则按“宽规则在前、例外在后”排列，最后匹配的规则生效。

agent 正文只放始终适用的内容：

```markdown
# 角色

你是 Simon，团队中的资深系统设计工程师。与开发者一起探讨、设计、评审、修订软件设计。

# 边界

- 只与单个开发者对接；不自主触发，不与其他 agent 交接。
- 不写代码、不编译、不部署；不做领域决策；不做过程记录与决策纪要；不做通用写作。
- 可以推荐方案、辅助决策，但最终由开发者拍板。

# 工作方式

处理设计诉求时，先加载 `design-cognition` skill，按其中的诉求路由，只加载一个诉求 reference。产出设计文档前运行结构检查脚本；不通过则修正或说明。
```

## skill

`skills/design-cognition/SKILL.md` 的 frontmatter：

```yaml
---
name: design-cognition
description: Simon 的设计认知：设计判断、固定六部分文档结构、评审与修订。开发者要求设计、评审、修订软件设计时使用。
metadata:
  opencode/autoinvoke: false
---
```

- `metadata.opencode/autoinvoke: false`：skill 不进入模型自动发现列表，由 simon agent 在系统提示中显式加载，避免其他 agent 自动触发。
- `description` 只描述触发面；正文不重复 agent 的角色与边界。

`SKILL.md` 正文包含：

1. 诉求路由表（来自 `source_prompt/index.md`）。
2. 固定六部分结构：背景与目标、场景设计、边界设计、实现设计、规格设计、测试设计。
3. 质量承诺：判断一致、设计可判断、设计判断可辩护、结构完整、评审意见有依据、跨技术栈复用。
4. reference 索引：十个诉求文件、`template.md`、`design.md`（仅追溯，默认不整篇加载）。
5. 加载规则：先路由，再只加载一个诉求 reference；不要一次加载全部。

## 结构检查脚本

`scripts/check_design_doc_structure.py` 只做结构检查，不做语义判断。

调用方式：

```text
python check_design_doc_structure.py <design.md>
```

- 退出码 0：六个部分齐全。
- 退出码 1：缺少部分；输出缺失的章节名。
- 不判断章节内容质量、不判断设计决策正确性。

## 使用指引

`build/opencode/使用指引.md` 说明安装、卸载、更新与最小检查；本身不部署。

- 安装：把 `build/opencode/agents/simon.md` 与 `build/opencode/skills/design-cognition/` 软链接到 opencode 配置目录（`~/.config/opencode`，Windows 为 `%USERPROFILE%\.config\opencode`）。
- 卸载：删除软链接，保留 `build/opencode/` 本体。
- 更新：改源后重新构建，软链接无需重装。
- 验证：新开 opencode 后 `@simon` 可见，`design-cognition` 可由 simon 显式加载。
